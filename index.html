About

I came to data science through the back door: first fixing a friend's spreadsheet, then rebuilding a receipt pipeline, then finding that most of the interesting work sits between the sensor and the dashboard, in the part nobody puts on a slide.

Most of my projects start with one question — can this be made boring? If a system needs a person to remember something every morning, it is not finished. I write plain HTML, depend on few libraries, and will take a two-hundred-line script over a framework that has to be explained to the next person.

Pipelines
SQLite, Python, scheduled sync. Small, restartable, observable.
Interfaces
Semantic HTML, one CSS file, no build step, works on a phone.
Provenance
Logging what changed, when, and why — so a result can be traced.

Research & projects

  1. 2026

    Edge telemetry for a vending machine

    Replaced a handwritten restock log with a scheduled sync into SQLite, plus a daily summary that a non-technical operator can read. Runs on a machine that is switched off most nights.

    SQLite · Python · cron · offline-first

  2. 2026

    Prompt provenance

    Every prompt change is versioned with the output it produced, so a regression can be attributed to a diff instead of a guess. Built for local models where vendor dashboards do not exist.

    LLM · logging · experiment tracking

  3. 2025

    Usable night-sky sites

    Turned a set of dated exposures into an index of where the sky is actually dark enough to bother, with the method written down well enough for someone else to repeat.

    data cleaning · mapping · reproducibility
